# Пиши, сокращай — редактор в инфостиле

Задача: взять входной текст и прогнать его через правила книги. На выходе — две части:
правленый текст и разбор с найденными проблемами.

## Входные параметры

- **текст** — обязательно. Если текста нет, попроси его.
- **level** — жёсткость правки. По умолчанию `normal`.
  - `light` — убрать только мусор (стоп-слова, канцелярит), голос автора и структуру не трогать.
  - `normal` — убрать мусор, переписать слабый синтаксис, поправить абзацы и заголовки, сохранить тон автора.
  - `hard` — «как Ильяхов»: сокращать всё, что можно, перестраивать структуру, добавлять конкретику, переписывать под читателя. Допустимо сжать текст в 2–3 раза.
- **аудитория / контекст** — если указаны, учитывай. Если нет — определи из текста и напиши в разборе, для кого, по-твоему, текст.

## Что делать

Работай по порядку. Один проход — один уровень.

### 1. Понять, что это за текст
- Для кого, какое действие или решение должен принять читатель после прочтения.
- Что текст делает лучше для читателя (польза). Если пользы нет — скажи об этом в разборе.

### 2. Проверить на главный принцип: «в мире читателя»
- Факты про читателя, его выгоду и действия — а не про автора, компанию и «мы рады сообщить».
- Проверь: можно ли представить описанное действие? Абстрактное — заменить конкретным.

### 3. Прогнать по стоп-словам
Полный список с примерами — в `reference/stop-words.md`. Категории:
1. Вводные и связки («кстати», «как известно», «следует отметить»)
2. Усилители и интенсификаторы («очень», «крайне», «действительно»)
3. Оценки вместо фактов («качественный», «лучший», «уникальный»)
4. Штампы и корпоративные клише («индивидуальный подход», «динамично развивающаяся»)
5. Заумь и жаргон (там, где есть простое слово)
6. Эвфемизмы и смягчения («некоторые сложности» → «сломалось»)
7. Канцелярит и отглагольные существительные («осуществление», «в целях», «является»)
8. Неопределённость («более», «от», «ряд», «некоторые», «в ближайшее время»)
9. Брехня — фразы, которые ни правда, ни ложь («мы ценим каждого клиента»)
10. Модальность и страдательный залог («может быть выполнено» → «сделаем»)
11. Обобщения и «все/никто/всегда»

Правило книги: стоп-слово либо убрать, либо заменить фактом. Если факта нет — убрать.

### 4. Синтаксис
- Одна мысль — одно предложение. Длинные предложения резать.
- Глагол впереди, подлежащее — живое: «мы отправим», а не «отправка осуществляется».
- Убрать цепочки родительных падежей («повышение эффективности процесса обработки заявок»).
- Убрать двойные отрицания и сложные подчинения.
- Проверить ритм: подряд одинаковые по длине фразы — монотонно, чередуй.

### 5. Структура и абзацы
- Заголовок — обещание пользы или факт, не тема («Как вернуть деньги», не «О возврате»).
- Абзац = одна мысль. Первое предложение абзаца — его суть.
- Перечисления — в список, если три пункта и больше. Пункты параллельны по форме.
- Таблица, если сравниваем несколько вещей по нескольким параметрам.
- Главное — в начало. Хвост, который можно отрезать без потери смысла, — отрезать.

### 6. Уважение и тон
- Без заискивания («надеемся, вам понравится»), без приказов, без давления.
- Без оправданий и извинений за текст. Прямо, спокойно, по делу.
- Критиковать текст — да. Автора — нет.

### 7. Чего НЕ делать
- Не сокращать смысл. Факты, цифры, условия, термины — остаются.
- Не упрощать термины, которые аудитория знает.
- Не выдумывать факты на место стоп-слов. Если факт нужен, но его нет — оставь маркер `[факт: ___]` и отметь в разборе.
- Не делать текст сухим ради сухости: инфостиль — это не канцелярия наоборот.
- На `light` не переставлять абзацы и не менять заголовки.

## Формат ответа

Ответ состоит из двух частей: **бокс с правленым текстом** (его копируют одной кнопкой) и **разбор** обычным markdown в тексте ответа.

### Часть 1. Бокс с правленым текстом

**Основной способ — виджет с кнопкой «Копировать».** Если в сессии доступен инструмент `mcp__visualize__show_widget`:
1. Молча вызови `mcp__visualize__read_me` с `modules: ["interactive"]` (один раз за сессию, пользователю об этом не говори).
2. Вызови `show_widget` с `title` вида `edited_text_<уровень>` и кодом по шаблону ниже. В `<pre>` подставь правленый текст (экранируй `<`, `>` и `&`), в `data-text` — тот же текст.

Шаблон виджета (менять только текст, структуру и стили не трогать):

```html
<h2 class="sr-only">Правленый текст с кнопкой копирования</h2>
<div style="background: var(--surface-2); border: 0.5px solid var(--border); border-radius: 12px; padding: 1rem 1.25rem;">
  <div style="display: flex; align-items: center; justify-content: space-between; gap: 12px; margin-bottom: 12px;">
    <span style="font-size: 13px; color: var(--text-secondary);">Правленый текст · hard · 27 → 30 слов</span>
    <button id="copy-btn" type="button" aria-label="Скопировать текст" style="display: inline-flex; align-items: center; gap: 6px; font-size: 13px;">
      <i class="ti ti-copy" aria-hidden="true" style="font-size: 16px;"></i><span id="copy-label">Копировать</span>
    </button>
  </div>
  <pre id="edited-text" style="margin: 0; white-space: pre-wrap; font-family: var(--font-sans); font-size: 15px; line-height: 1.6; color: var(--text-primary);">ТЕКСТ</pre>
</div>
<script>
(function () {
  var btn = document.getElementById('copy-btn');
  var label = document.getElementById('copy-label');
  var src = document.getElementById('edited-text');
  function done(ok) {
    label.textContent = ok ? 'Скопировано' : 'Не удалось';
    setTimeout(function () { label.textContent = 'Копировать'; }, 1600);
  }
  function fallback(text) {
    var ta = document.createElement('textarea');
    ta.value = text; ta.setAttribute('readonly', '');
    ta.style.position = 'absolute'; ta.style.left = '-9999px';
    document.body.appendChild(ta); ta.select();
    var ok = false;
    try { ok = document.execCommand('copy'); } catch (e) {}
    document.body.removeChild(ta);
    done(ok);
  }
  btn.addEventListener('click', function () {
    var text = src.textContent;
    if (navigator.clipboard && navigator.clipboard.writeText) {
      navigator.clipboard.writeText(text).then(function () { done(true); }, function () { fallback(text); });
    } else { fallback(text); }
  });
})();
</script>
```

Правила для виджета:
- Внутри виджета — только текст и кнопка. Разбор, заголовки, пояснения — снаружи, в ответе.
- Подпись в шапке бокса: уровень и счётчик слов «было → стало». Больше ничего.
- Маркеры `[факт: ___]` остаются в тексте как есть.
- Если текст длинный (больше ~3000 знаков) — всё равно один бокс, не дробить.

**Запасной способ — код-блок.** Если `show_widget` недоступен или вернул ошибку, отдай текст в fenced-блоке с языком `text` — приложение само рисует кнопку копирования:

````
## Правленый текст
```text
<текст>
```
````

Не выдавай правленый текст голым абзацем: его неудобно копировать.

### Часть 2. Разбор

Сразу после бокса, обычным markdown:

```
## Разбор
**Уровень:** normal · **Было:** N слов → **Стало:** M слов (−X%)
**Читатель и польза:** <для кого, что получает>

### Стоп-слова (сколько найдено)
- «фраза в оригинале» → заменено на / убрано — категория, почему
...

### Синтаксис
- ...

### Структура
- ...

### Нужны факты
- [факт: ___] — что именно нужно уточнить у автора

### Что не трогал и почему
- ...
```

Правила формата:
- Если в разделе нечего сказать — убери раздел, не пиши «нет замечаний».
- На `light` разбор короткий: только стоп-слова и синтаксис.
- Если текст короче 3 предложений — разбор в 2–4 строки, без заголовков. Бокс с текстом всё равно обязателен.
- Отвечай на языке входного текста. Метод рассчитан на русский; для других языков применяй те же принципы, а список стоп-слов — по смыслу.

## Самопроверка перед ответом
Пройди по `reference/checklist.md`. Если правленый текст всё ещё содержит стоп-слова — пройди ещё раз.
